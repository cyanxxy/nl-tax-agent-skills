# Extended workflow manual-entry gate

This reference applies to annual 2026, international migration/nonresident
2025/2026, ICP and OSS/IOSS. Read
`../nl-tax-shared-resources/reference/workflow-scopes.yaml` for the exact
workflow/year/form/scheme/period identity and only-file path, then the relevant
owning skill's output contract already named by that skill. This file does not
establish a reviewed final form or invent portal labels.

## Blockers before any output steps

Check the current workpack's generation confirmation, identity, source ledger,
required note/source human content reviews, exact workflow/schema review,
mapper readiness, open facts and stale markers. Annual 2026 and international
2026 additionally need year-end actual evidence and their exact final annual
form review; a provisional 2026 map is never a substitute. Current extended
workflow policy caps readiness at `draft`, so its review blocker remains open.

While any source-content or schema review is pending, or the draft-policy
ceiling, a stale or unconfirmed map, or an affected treatment or
reconciliation gap remains, show only **Blockers**, with no entry amounts or
filing steps, and write no checklist.
Name each required review or missing fact without repeating amounts. Include
no amounts to enter, filing/payment steps, document-entry instructions or
partial checklist. Write nothing, even with save consent. Return control to
the owning workflow for preparation or maintainer review. The generic
partial-input rule never overrides this gate. Taxpayer acceptance, browser
research, arithmetic tests, hashes and agent self-checks cannot clear review.

ICP customer IDs and OSS/IOSS registration/payment identifiers are supplied
by the human separately. A dated human identity-verification fact must be
established before a checklist can be available; an alias-only dataset is not
a complete filing dataset. Never request or store the actual identifiers.

## Future reviewed checklist contract

After a maintainer has published reviewed source/form coverage and the actual
workflow policy permits readiness, a checklist still requires explicit user
intent and a confirmed current workpack/map matching every identity dimension.
Use only established manual-entry rows; conceptual `internal_routing` records
are never portal entries. If the reviewed step/label resource is missing, the
missing exact resource is a blocker; do not use these general checks as filing
steps or borrow the resident 2025/provisional/domestic VAT sequence.

Annual 2026 needs its actual annual rows and annual Box 3 treatment. M/C needs
the confirmed form, residence/insurance intervals, qualification evidence,
resolved treaty positions and its distinct reviewed inventory. ICP needs
verified customer identities, goods/services coverage, corrections and
same-coverage reconciliation of the ICP rubric 3 total to btw-aangifte rubric
3b. OSS needs the confirmed scheme and period,
verified destination rates, conversion, country grid, original-period
corrections and country-specific payable/refund treatment. Input VAT does not
reduce OSS payable. No workflow's totals substitute for another's figures.

Any permitted checklist names an explicit human subject for every official
action. The taxpayer or authorized human personally opens the correct filing
environment, checks screen labels, supplies the excluded identifiers, reviews,
signs, transmits and retains confirmation. The assistant never performs these
actions. Saving is only to that workflow's existing `## Manual-entry checklist`
section with current-session consent; no separate checklist file is created.
