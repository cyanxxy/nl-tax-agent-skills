# OSS output contract

Use templates/oss-workpack.md for one confirmed scheme/year/period. Save all
`##` headings in template order; unopened collection sections hold Not yet
reviewed. Chat shows only filled Markdown and no Appendix A/B YAML. Every
rate, destination, amount, scheme fact, correction and zero/n/a answer carries
F/U/A/C provenance; missing is ? with Q/M rows. Assumptions cannot establish
legal eligibility, registration or destination rates.

The owner writes all sections except mapper-owned Field map summary, Appendix
B and own gaps, and companion-owned Manual-entry checklist. They start not
yet mapped/not requested. No source clearance means no entry-amount checklist.
The owner only adds the shared STALE line to existing map/checklist sections
after a changed fact; their owners rebuild values.

Appendix A is exactly one YAML block, nl-tax-workpack version 2.0 and template
keys: workflow oss_<scheme>_<year>_<period>, tax_year 2025/2026, scheme
union/non_union/ioss, period Q1..Q4 for Union/non-Union or M01..M12 for IOSS,
queued_workflow null and sections oss_scope, oss_transactions, oss_corrections,
oss_reconciliation, confirm. Sources used equals sources_loaded; include only
consulted applicable source IDs, no 2026 customs source in a 2025 workpack.
File, profile and map share scheme/year/period. Appendix B is not yet mapped
or exactly one mapper-owned current-schema oss_return map with matching
scheme/year/period. Internal totals are calculations, never invented entry boxes.

Use STATUS: DRAFT — N deferred section(s) — not for filing for any source,
form, registration, rate, incomplete-period, treatment or reconciliation blocker;
name blockers even when N is zero. The shipped scope keeps readiness draft
even after section/source checks pass; never set review_ready or COMPLETE
DRAFT FOR REVIEW while this ceiling applies. All status surfaces agree.
The human always supplies genuine registration identifiers
and payment instructions separately.

## Agent checks

Check structure/provenance on partial consented saves and completeness/
calculation at generation. The mapper records checked_by_agent; research or
checks never create human review or promote readiness.

- Scheme is confirmed, Netherlands identification established, dates/period
  match registration and filename, and non_union eligibility is actually met.
  Incomplete calendar periods stay draft; annual IOSS or monthly Union is rejected.
- Current row country/category/rate/origin and VAT treatment have dated
  evidence; rates do not come from memory. IOSS uses payment timing and
  eligibility/customs-base screens for its year; KOR conflicts remain open.
- Original-currency totals, ECB rate/date/direction and EUR conversion reconcile;
  the rate is the ECB rate for the period's last day or, when none was
  published that day, the next ECB publication day, with the date recorded;
  source VAT and formula checks are distinct and form precision is confirmed.
- Prior corrections reconcile original figures, already reported deltas and
  target totals; later credit notes never appear in both grids. The three-year
  window is measured from the original period's due date, never from its
  actual filing date; out-of-window and terminated-registration routing is
  visible and the scheme is unchanged.
- Country current VAT and corrections equal that country's own rows, and
  country balances include only that country's deltas; payable sums positive
  balances and each negative balance is separate refund-review material.
  Input VAT and a different country's negative balance never reduce payable.
- All ev/A/Q/M references resolve; Sources used equals sources_loaded without
  duplicates; review/form coverage remains blocked until real human attestation.
- Map/readiness/confirmation agree and no stale value is used. The mapper alone
  writes maps; a permitted explicit request is needed for the companion checklist.
- No full identifiers, names/addresses, copied evidence, hashes or payment
  references are stored. Every account/portal action names the human, and the
  standalone Not submission advice names human-only Mijn Belastingdienst Zakelijk
  entry, signing and submission.

Current shared workflow-scopes.yaml maximum_readiness is draft; retain this
ceiling even if individual evidence, source-content or schema checks are
complete. Only a maintainer activation of the exact scope/reviewed map can
change it. Do not offer a checklist containing entry amounts in this bundle.
